### Decisions and open questions in Phase 3

- **A few `gcloud` facts can only be settled live**, and are isolated in the `GoogleCloud` adapter (not yet written): how to tell a **free-trial** billing account, how to check the **project quota** before creating one, and the org-policy check for **public services**. The fake answers them, so the flow is tested; the commands themselves need the live install (the novice test).
- **The sending test (step 7) runs from setup** over SMTP, before the server's own checks, and records each account's Sent mode in `universal-mail-state` as a new version.
- **`{key}` is kept in the progress file** (not a password or key, but it keeps the address hard to guess); needed to resume.

- **Image signature.** The adapter checks the image is from the official repository, pinned by digest, and present. Verifying a *signature* needs the release pipeline to sign images first; open until then.
- **The server reads its secrets at start** (`--set-secrets …:latest`), so a new state version (step 7) takes effect on the next start; the server's own periodic re-read is still to build.
- **The test email stays where it lands** (the account's Inbox, and Sent if the provider files it). Setup never deletes mail; the email says it can be deleted, and the AI never sees it (system Message-ID).
- **A provider found only by autoconfig or SRV** gets a generic app-password hint (its domain, "App passwords"). Better wording for unknown providers is Phase 5 polish.
- **The real DNS lookups (`realLookups`) are untested by design**: tests never touch the network. The live install exercises them, and `detect-detail` logs what they found.
- **The check is the server's, and setup only asks.** The server has the passwords; setup has the signing key it generated, so it can prove it's setup without any new secret. The `google` stage is run from setup inside Check and fix (SET-81). The `live:` stage is **not built: a decision for the owner** (docs/OPEN-QUESTIONS.md). `apps` is on the page as "last used" per app (PG-17) rather than a pass/fail stage.
- **Where the check leaves its trail:** the server's log has one `check_stage_failed` line per failure (code, error name, stack frames); setup's log has every attempt and the whole report.

Every planned behaviour is built and tested, including the `live:` stage (the owner's choice, 2026-09-26). What remains needs the owner or the live Google install: see **docs/OPEN-QUESTIONS.md**, and the live-install checklist there.
